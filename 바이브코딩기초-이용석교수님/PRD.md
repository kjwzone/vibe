# PRD 할 일 관리 앱

> 상태 v0.2 / 작성일 2026-10-17
> v0.1 대비 변경 사항은 사용자 요구(카테고리, 진행률, 순수 JS)를 반영한 것이다.

## 1. 배경과 목적

- 매일 10~20개 정도의 할 일을 적고, 끝낸 일을 체크하며, 하루 진행 상황을 한눈에 보는 개인용 앱이다.
- 바이브코딩 기초 수업의 실습 결과물이므로 작고 완결된 형태로 끝까지 만든다.

## 2. 확정된 조건

| # | 조건 |
|---|------|
| C1 | 사용자는 본인 한 명이며 로그인이 없다. |
| C2 | 브라우저에서 바로 실행된다. 빌드와 설치가 필요 없다. |
| C3 | 새로고침과 브라우저 재시작 후에도 데이터가 유지된다. |
| C4 | 순수 자바스크립트(바닐라 JS)만 사용한다. 프레임워크와 번들러는 쓰지 않는다. |
| C5 | 하루 10~20개 규모를 기준으로 하며 대용량 최적화는 하지 않는다. |

## 3. 가정 (확인 필요)

| # | 가정 | 이유 |
|---|------|------|
| A1 | 데이터는 브라우저 localStorage에 저장하고 서버는 없다. | C3를 가장 단순하게 만족한다. |
| A2 | 파일은 `index.html`, `style.css`, `app.js` 세 개로 나눈다. | 역할이 분리되어 읽기 쉽고 여전히 단순하다. |
| A3 | 카테고리는 업무, 개인, 공부 세 가지로 고정하고 사용자 추가는 없다. | 요구 범위 그대로. |
| A4 | UI는 한국어이며 모바일 화면도 지원한다. | 사용자 환경 기준. |
| A5 | 날짜 구분은 하지 않고 하나의 목록을 계속 쓴다. 하루가 지나도 목록은 유지된다. | 일별 기록은 요구에 없음. |

## 4. 핵심 사용자 시나리오

1. 입력창에 할 일을 적고 카테고리를 고른 뒤 Enter 또는 추가 버튼을 누른다.
2. 체크박스를 눌러 완료 처리하면 취소선이 그어지고 진행률이 갱신된다.
3. 항목의 제목이나 카테고리를 수정하거나 삭제한다.
4. 카테고리 탭(전체/업무/개인/공부)으로 목록을 걸러 본다.
5. 상단에서 오늘의 진행률을 확인한다.
6. 브라우저를 닫았다 열어도 목록과 완료 상태가 그대로 남아 있다.

## 5. 기능 요구사항

### 필수 (MVP)

| ID | 요구사항 | 완료 기준 |
|----|----------|-----------|
| F1 | 할 일 추가 | 제목과 카테고리(업무/개인/공부)를 지정해 추가한다. 공백만 있는 제목은 추가되지 않고, 추가 후 입력창이 비워진다. |
| F2 | 할 일 수정 | 제목과 카테고리를 바꾸고 저장하면 반영된다. 빈 제목으로는 저장되지 않는다. |
| F3 | 할 일 삭제 | 삭제하면 목록에서 즉시 사라지고 저장소에서도 지워진다. |
| F4 | 완료 체크 | 체크하면 완료 표시, 다시 누르면 해제된다. |
| F5 | 카테고리 분류 | 각 항목에 카테고리 배지가 보이고, 탭으로 카테고리별 목록을 볼 수 있다. |
| F6 | 진행률 보기 | 전체 완료 수/전체 수와 퍼센트를 진행 바로 보여준다. 항목이 0개면 0%로 표시한다. |
| F7 | 카테고리별 진행률 | 업무/개인/공부 각각의 완료 수/전체 수를 보여준다. |
| F8 | 영구 저장 | 추가·수정·삭제·체크 즉시 localStorage에 저장되고, 새로고침 후 복원된다. |

### 선택 (MVP 이후)

- 완료 항목 일괄 삭제.
- 마감일과 우선순위.
- 드래그로 순서 변경.
- 다크 모드.
- 데이터 내보내기/가져오기(JSON).

## 6. 비기능 요구사항

- 최신 Chrome, Edge, Safari 모바일에서 동작한다.
- `index.html`을 더블클릭해 여는 것만으로 실행된다(`file://`에서도 동작).
- 키보드만으로 추가(Enter), 체크, 삭제가 가능하다.
- 외부 서버나 외부 라이브러리를 사용하지 않는다. 사용자 입력은 `textContent`로 출력해 스크립트가 실행되지 않게 한다.
- localStorage 값이 깨져 있거나 읽을 수 없어도 앱이 멈추지 않고 빈 목록으로 시작한다.

## 7. 범위 밖

- 로그인, 여러 기기 동기화, 팀 공유.
- 알림과 푸시.
- 카테고리 추가·삭제·이름 변경.
- 날짜별 기록과 통계.

## 9. 데이터 모델

```json
{ "id": "문자열", "title": "문자열", "category": "업무|개인|공부", "done": false, "createdAt": "ISO 날짜" }
```

- localStorage의 한 키(예 `todos`)에 배열로 저장한다.
- 진행률은 저장하지 않고 항상 목록에서 계산한다.

## 10. 성공 기준

- F1~F8이 모두 동작한다.
- 15개 항목을 넣고 체크·수정·삭제한 뒤 새로고침해도 상태가 동일하다.
- 진행률 숫자가 실제 완료 수와 항상 일치한다. 진행률은 필터와 무관하게 전체 기준이다.
- 모바일 너비 360px에서 가로 스크롤 없이 사용할 수 있다.
- 외부 의존성이 0개다.

## 11. 수동 테스트 시나리오

1. 빈 제목 추가 시도 → 추가되지 않는다.
2. 카테고리별로 항목 추가 → 배지와 카테고리별 진행률이 맞다.
3. 일부 체크 → 전체와 카테고리별 진행률이 갱신된다.
4. 항목 수정(제목+카테고리 변경) → 카테고리 진행률이 함께 바뀐다.
5. 항목 삭제 → 진행률 분모가 줄어든다.
6. 새로고침 → 모든 상태가 유지된다.
7. 개발자 도구에서 `todos` 값을 깨뜨리고 새로고침 → 앱이 빈 목록으로 열린다.
