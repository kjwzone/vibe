# 클로드 코드 단계별 프롬프트

`PRD.md`(v0.2)를 5단계로 나눈 프롬프트 모음이다.
각 단계를 순서대로 붙여 넣고, 단계마다 "확인 방법"을 통과한 뒤 다음으로 넘어간다.

## 사용 규칙

- 한 번에 한 단계만 실행한다. 다음 단계 프롬프트를 미리 붙여 넣지 않는다.
- 단계가 끝나면 `checklist.md`에 체크가 되었는지, `context-notes.md`에 결정이 기록되었는지 본다.
- 막히면 추측으로 고치지 말고 에러 메시지 원문을 그대로 붙여 넣어 원인을 먼저 묻는다.
- 단계 2부터 새 소스 파일 첫 줄에는 한 줄짜리 한국어 역할 주석을 넣는다(프로젝트 CLAUDE.md 규칙).

---

## 1단계 계획과 작업 문서 만들기

목표는 코드를 쓰기 전에 계획, 체크리스트, 결정 기록을 갖추는 것이다.

```text
이 폴더의 PRD.md를 읽고 할 일 관리 앱의 구현 계획을 세워줘.
아직 코드는 작성하지 마.

1. checklist.md를 만들어줘. PRD의 F1~F8을 구현 순서대로 체크박스 작업으로 쪼개줘.
   작업 하나는 한 번의 커밋으로 설명할 수 있는 크기여야 해.
2. context-notes.md를 만들어줘. 지금까지 확정된 결정(순수 JS, localStorage,
   파일 3개 구성, 카테고리 3개 고정)과 그 이유를 적고, 이후 결정은 계속 덧붙여줘.
3. PRD의 열린 질문 3개 중 내가 아직 답하지 않은 것이 있으면 기본값을 제안해줘.
   내가 승인하기 전에는 그 가정으로 진행하지 마.
4. 위험하거나 모호한 부분이 있으면 목록으로 알려줘.

끝나면 파일 2개의 내용을 요약해서 보여주고, 내 확인을 기다려.
```

확인 방법
- `checklist.md`가 F1~F8을 모두 포함한다.
- `context-notes.md`에 결정과 이유가 적혀 있다.
- 코드 파일이 아직 하나도 없다.

## 2단계 화면 뼈대와 스타일

목표는 동작은 없고 모양만 있는 정적 화면을 만드는 것이다.

```text
checklist.md의 첫 작업부터 진행해줘. 이번 단계에서는 화면만 만들고 동작은 넣지 마.

- index.html, style.css, app.js 세 파일을 만들어줘. 순수 JS이고 외부 라이브러리와
  CDN은 쓰지 마. app.js는 이번 단계에서 빈 틀만 둬.
- 소스 파일 첫 줄에 한 줄 한국어 역할 주석을 넣어줘.
- PRD 8장의 화면 구성을 따라줘. 상단 진행률 영역(전체 진행 바 + 업무/개인/공부
  숫자), 입력창 + 카테고리 선택 + 추가 버튼, 카테고리 탭(전체/업무/개인/공부),
  할 일 목록 영역 순서야.
- 예시 항목 3개를 HTML에 임시로 넣어 모양을 확인할 수 있게 해줘. 다음 단계에서 제거할 거라
  주석으로 표시해줘.
- 모바일 너비 360px에서 가로 스크롤이 생기지 않게 해줘.
- 카테고리 배지는 업무/개인/공부가 색으로 구분되게 해줘.
- 웹 UI 작업이니 frontend-design 플러그인을 활용해줘.

끝나면 checklist.md에 체크하고 context-notes.md에 결정을 덧붙여줘.
그 뒤 변경 내용을 한 문장으로 설명할 수 있으면 커밋해줘.
```

확인 방법
- `index.html`을 더블클릭하면 화면이 열린다.
- 브라우저 폭을 360px로 줄여도 가로 스크롤이 없다.
- 카테고리 배지 색이 서로 다르다.

## 3단계 추가, 수정, 삭제, 완료와 저장

목표는 핵심 데이터 흐름(F1~F4, F8)을 동작시키는 것이다.

```text
checklist.md의 다음 작업을 진행해줘. 이번 단계는 데이터 로직과 저장이야.

- 2단계의 임시 예시 항목을 제거하고, 목록을 데이터 배열에서 그려줘.
- 데이터 모델은 PRD 9장대로 { id, title, category, done, createdAt }야.
  localStorage 키 하나(todos)에 배열로 저장해줘.
- 구현할 기능
  - F1 추가. 공백뿐인 제목은 거부하고, 추가 후 입력창을 비우고 Enter로도 추가돼야 해.
  - F2 수정. 제목과 카테고리를 바꿀 수 있고 빈 제목으로는 저장되지 않아야 해.
  - F3 삭제.
  - F4 완료 체크와 해제. 완료된 항목은 취소선으로 보여줘.
  - F8 모든 변경 직후 저장하고, 페이지 로드 때 복원해줘.
- localStorage 값이 깨져 있거나 읽을 수 없어도(JSON 오류, 접근 차단) 앱이 멈추지 않고
  빈 목록으로 시작해야 해.
- 사용자 입력은 innerHTML이 아니라 textContent로 출력해줘.
- 함수는 작게 나누고, 화면을 그리는 함수와 데이터를 바꾸는 함수를 분리해줘.

끝나면 PRD 11장 테스트 시나리오 1, 6, 7을 직접 실행해보고 결과를 알려줘.
체크리스트를 갱신하고, 기능 단위로 나눠서 커밋해줘.
```

확인 방법
- 항목을 추가하고 새로고침해도 그대로 남는다.
- 공백만 입력하면 추가되지 않는다.
- 개발자 도구에서 `todos` 값을 깨뜨리고 새로고침해도 빈 목록으로 열린다.

## 4단계 카테고리 필터와 진행률

목표는 분류와 진행률(F5~F7)을 완성하는 것이다.

```text
checklist.md의 다음 작업을 진행해줘. 이번 단계는 카테고리 필터와 진행률이야.

- F5 카테고리 탭(전체/업무/개인/공부)을 동작시켜줘. 선택한 탭이 눈에 띄게 표시돼야 하고,
  빈 목록일 때는 안내 문구를 보여줘.
- F6 전체 진행률을 진행 바, 완료 수/전체 수, 퍼센트로 보여줘. 항목이 0개면 0%로 표시해.
- F7 카테고리별 완료 수/전체 수를 업무, 개인, 공부 각각 보여줘.
- 진행률은 저장하지 말고 매번 목록에서 계산해줘.
- 진행률은 현재 탭과 상관없이 항상 전체 기준이야.
- 추가, 수정(카테고리 변경 포함), 삭제, 체크 때마다 진행률이 즉시 갱신돼야 해.
- 퍼센트는 반올림해서 정수로 보여줘.

끝나면 PRD 11장 테스트 시나리오 2, 3, 4, 5를 실제로 실행해보고,
각 시나리오의 기대 결과와 실제 결과를 표로 알려줘.
체크리스트를 갱신하고 커밋해줘.
```

확인 방법
- 카테고리별 숫자의 합이 전체 숫자와 같다.
- 항목 하나를 업무에서 공부로 바꾸면 두 카테고리 숫자가 함께 바뀐다.
- 탭을 바꿔도 상단 진행률은 변하지 않는다.

## 5단계 전체 검증과 마무리

목표는 PRD 성공 기준을 모두 확인하고 정리하는 것이다.

```text
마지막 점검을 해줘. 새 기능은 추가하지 마.

1. PRD 11장의 수동 테스트 시나리오 1~7을 처음부터 끝까지 다시 실행하고,
   시나리오별로 통과/실패를 표로 알려줘.
2. PRD 10장 성공 기준을 하나씩 확인해줘.
   - 항목 15개 입력 후 체크, 수정, 삭제하고 새로고침해도 상태 동일
   - 진행률 숫자가 항상 실제 완료 수와 일치
   - 360px 너비에서 가로 스크롤 없음
   - 외부 의존성 0개
3. 실패하는 항목이 있으면 원인을 에러 메시지나 실제 동작으로 확인한 뒤에 고쳐.
   추측으로 고치지 마.
4. 내가 요청하지 않은 코드, 사용하지 않는 함수와 변수가 남아 있으면 찾아서 알려줘.
   지우기 전에 목록부터 보여줘.
5. checklist.md가 전부 체크되었는지, context-notes.md에 마지막 결정이 기록되었는지 확인해줘.
6. 남은 변경을 의미 단위로 커밋해줘. 푸시나 배포는 하지 마.

끝나면 통과한 것, 못한 것, 다음에 할 만한 선택 기능을 짧게 정리해줘.
```

확인 방법
- 시나리오 1~7과 성공 기준이 모두 통과로 보고된다.
- `checklist.md`가 전부 체크되어 있다.
- 커밋이 기능 단위로 나뉘어 있고 푸시는 하지 않았다.
