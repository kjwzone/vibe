# 퀴즈 정확성 검증

`src/data/questions.json`의 **전체 문항**에서 정답, 중복 문제, 모호한 표현, 해설을 점검한다.
기준은 CLAUDE.md의 "지켜야 할 요구사항"과 `교차검증가이드라인.png`, PRD 8장 검수 체크리스트다.

**이 스킬은 보고만 한다.** 파일을 고치지 않는다. 수정은 사용자가 승인한 문항만, 별도 요청으로 한다.

## 1. 기계 검사부터

1. `npx vitest run src/lib/questions.test.ts`를 실행해 스키마, id 중복, 보기 4개·중복, `answerIndex` 범위, 글자 수를 확인한다. 실패하면 그 내용을 맨 앞에 보고한다.
2. 그다음 문항을 하나씩 읽으며 아래 2~5장을 점검한다.

## 2. 정답 점검

- `options[answerIndex]`가 질문의 정답이 맞는지 확인한다.
- 해설이 말하는 정답과 `options[answerIndex]`가 같은지 확인한다.
- 다른 보기도 정답이 될 수 있는지 확인한다. (해석, 기준, 시점에 따라)
- 해설 속 연도·수치·인물·지명이 맞는지 확인한다.

## 3. 중복 점검

- 같은 사실을 묻는 문제(문장이 달라도 정답과 근거가 같으면 중복)를 찾는다.
- 한 문제의 해설이 다른 문제의 정답을 알려 주는 경우(힌트 노출)도 찾는다.
- 카테고리가 달라도 함께 비교한다. (예: 한국사와 일반상식의 한글 관련 문제)

## 4. 모호한 표현 점검

- '가장·최초·최대·유일' 같은 최상급 표현에 측정 기준, 범위, 시점이 있는지 확인한다.
- '현재·최근'처럼 시점이 빠진 표현, 시점에 따라 바뀌는 사실(인구, 현직 인물, 기록)이 있는지 확인한다.
- '모두 정답', '정답 없음' 보기와 정답만 유독 길거나 형식이 다른 보기가 있는지 확인한다.
- 정치·종교 등 논쟁적 소재가 있는지 확인한다.

## 5. 해설 점검

- 1~2문장인지, 정답의 근거를 설명하는지 확인한다.
- 질문과 용어가 어긋나지 않는지 확인한다. (예: 질문은 '서울', 해설은 '한양')
- 논란이 있는 내용이면 주류 학설을 따르고 근거를 밝혔는지 확인한다.

## 6. 근거와 "확인 필요"

- 사실 관계는 확실히 아는 것만 "확인됨"으로 쓴다.
- 기억만으로 확신할 수 없거나, 출처마다 값이 다르거나, 학설이 갈리면 **"확인 필요"** 로 보고한다. 추측으로 정답을 바꾸라고 제안하지 않는다.
- 웹 검색을 쓸 수 있으면 "확인 필요" 항목을 2개 이상의 출처로 확인하고 출처 이름을 적는다. 쓸 수 없으면 "확인 필요"로 남긴다.
- `context-notes.md`의 "열린 질문"에 이미 있는 항목은 그렇다고 표시한다.

## 7. 보고 형식

첫 줄에 요약을 쓴다. (점검 문항 수, 테스트 결과, 오류·확인 필요·개선 권장 개수)

```
## 오류 (정답이 틀렸거나 정답이 둘 이상)
### SCI-003
- 문제: ...
- 근거: ...
- 수정안: ...

## 확인 필요 (근거 부족)
### HIS-009
- 의심 내용: ...
- 확인할 것: ... (어떤 출처에서 무엇을)

## 개선 권장 (모호한 표현, 해설, 중복)
### GEO-005
- 유형: 모호한 표현 / 해설 / 중복
- 내용: ...
- 개선안: ...

## 문제 없음: N문항
```

해당 항목이 없는 절은 "없음"으로 적는다. 마지막에 어떤 항목을 고칠지 묻는다.

## 관련 스킬

- `/quiz-validate [카테고리]`: 최상급 표현만 자세히 점검
- `/quiz-stats`: 개수, 분포, 정답 위치 편향
