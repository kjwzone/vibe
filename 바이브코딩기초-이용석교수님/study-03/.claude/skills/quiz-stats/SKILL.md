# 퀴즈 통계·분포 분석

`src/data/questions.json` 전체의 문제 수, 카테고리별·난이도별 분포, 정답 보기의 편향을 분석한다.

**이 스킬은 보고만 한다.** 파일을 고치지 않는다.

## 1. 집계 실행

프로젝트 루트(`study-03`)에서 아래 스크립트를 실행한다. 숫자는 직접 세지 말고 스크립트 출력을 그대로 쓴다.

```bash
node .claude/skills/quiz-stats/stats.mjs
```

스크립트는 다음을 마크다운 표로 출력한다.
- 전체 문제 수
- 카테고리별 문제 수와 easy / normal / hard 개수, PRD 권장 분포(10문제당 4·4·2)와 비교한 결과
- 정답 보기 위치(1~4번) 분포: 카테고리별, 전체, 카이제곱 통계량
- 같은 정답 위치가 3번 이상 연속된 구간
- 정답이 혼자 가장 긴 보기인 문제 (PRD 8장 "정답만 길면 힌트가 됨")

## 2. 해석 기준

- **라운드 분량**: 카테고리마다 10문제 이상이어야 게임이 돈다. 10문제보다 많으면 게임은 라운드마다 10문제를 무작위로 뽑는다(`QUESTIONS_PER_ROUND`).
- **난이도**: 카테고리마다 easy 4 · normal 4 · hard 2 이상을 권장한다. 문제가 10개보다 많은 카테고리는 무작위로 뽑으므로, 한 판의 난이도 구성은 비율에 따라 달라진다고 덧붙인다.
- **정답 위치 편향**:
  - 한 위치가 기대값(문제 수 ÷ 4)의 2배 이상이거나 0개면 "쏠림"으로 본다.
  - 카이제곱 통계량이 7.81 이상이면 전체 분포가 통계적으로 치우쳤다고 본다.
  - 게임은 보기 순서를 섞어서 보여 주므로(F-02) 플레이어에게는 영향이 없다. 원본 데이터 작성 습관을 점검하는 용도라고 밝힌다.
- **정답 길이 편향**: 정답이 혼자 가장 긴 보기인 비율이 40%를 넘으면 힌트가 될 수 있다고 본다. 이 편향은 보기를 섞어도 남으므로 정답 위치 편향보다 중요하다.

## 3. 보고 형식

1. 요약 3줄 이내: 전체 문제 수, 가장 눈에 띄는 분포 문제, 조치가 필요한지 여부.
2. 스크립트가 출력한 표.
3. 해석: 2장 기준으로 문제가 되는 항목만 짧게 적는다. 없으면 "기준을 벗어난 항목 없음"으로 적는다.
4. 제안: 필요하면 `/quiz-add [카테고리] [난이도]`로 어떤 문제를 보충하면 좋을지, 또는 어느 문항의 보기 길이를 맞추면 좋을지 적는다.

## 관련 스킬

- `/quiz-range [시작] [끝]`: 번호 범위만 검토
- `/quiz-check`: 정답과 내용의 정확성 검증
