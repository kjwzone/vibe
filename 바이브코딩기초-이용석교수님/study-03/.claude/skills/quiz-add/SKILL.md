# 새 퀴즈 후보 작성

카테고리와 난이도에 맞는 새 문제를 기존 형식으로 만들고, 검증 가이드라인을 통과하는지 스스로 확인한 뒤 **후보로 제시**한다.

**`src/data/questions.json`은 고치지 않는다.** 지금 구조는 총 40문제·카테고리별 10문제로 고정되어 있다. 테스트(`questions.test.ts`)가 이 개수를 검사하고, `getRoundQuestions()`는 카테고리 문제를 전부 출제한다. 그래서 문제를 하나 더 넣으면 테스트가 실패하고 라운드가 11문제가 된다. 후보를 반영하는 방법은 7장을 따른다.

## 1. 인수 해석

- 카테고리: $0
- 난이도: $1

| 카테고리 인수 | `category` | id 접두어 |
| --- | --- | --- |
| `history` 또는 `한국사` | history | HIS |
| `science` 또는 `과학` | science | SCI |
| `geography` 또는 `지리` | geography | GEO |
| `general` 또는 `일반상식` | general | GEN |

| 난이도 인수 | `difficulty` |
| --- | --- |
| `easy` 또는 `쉬움` | easy |
| `normal` 또는 `보통` | normal |
| `hard` 또는 `어려움` | hard |

- 카테고리가 비어 있거나 표에 없는 값이면 만들지 않는다. 대신 "사용법: /quiz-add 지리 normal"과 쓸 수 있는 값을 알려 준다.
- 난이도가 비어 있으면 `normal`로 만들고, 그렇게 정했다고 알린다. 표에 없는 값이면 만들지 않고 사용법을 알려 준다.

## 2. 작성 전 확인

1. `src/data/questions.json`에서 같은 카테고리 문항을 모두 읽는다.
2. 이미 있는 주제·정답과 겹치지 않는 소재를 고른다. 같은 사실을 다른 말로 묻는 것도 겹침으로 본다.
3. 같은 카테고리·난이도의 기존 문항을 보고 문장 길이와 말투(`~은?`, `~일까?`)를 맞춘다.

## 3. 형식 (PRD 8장)

```json
{
  "id": "GEO-011",
  "category": "geography",
  "question": "문제 본문 (80자 이내)",
  "options": ["보기1", "보기2", "보기3", "보기4"],
  "answerIndex": 0,
  "explanation": "해설 1~2문장.",
  "difficulty": "normal",
  "source": "근거 출처 (교과서·백과사전 항목명 등)"
}
```

- `id`는 같은 접두어의 가장 큰 번호 + 1로, 세 자리로 맞춘다. 실제 id는 반영 방법에 따라 바뀔 수 있다고 적는다.
- `options`는 4개이고 각각 20자 이내이며 서로 겹치지 않는다.
- `answerIndex`는 0~3이며 원본 보기 순서 기준이다. 같은 카테고리에서 정답 위치가 한쪽으로 몰리지 않게 정한다.
- `explanation`은 1~2문장이다. 정답의 근거를 쓰고, 필요하면 헷갈리는 보기가 왜 아닌지도 적는다.
- AI가 만든 문제이므로 `source`에 근거를 적는다(PRD 8장). 확인할 수 없는 출처를 지어내지 않는다. 근거가 불확실하면 "교차 확인 필요"로 적는다.

## 4. 난이도 기준

- **easy**: 중학생 대부분이 아는 상식이다. 보기 중 정답이 분명하게 구별된다.
- **normal**: 교과서 수준의 구체적 지식(인물, 연도, 수치, 위치)이 필요하다.
- **hard**: 심화 지식이 필요하거나, 그럴듯한 오답 보기가 섞여 있다. 다만 정답은 여전히 하나뿐이어야 한다.

## 5. 검증 체크리스트

후보를 내기 전에 모두 확인하고, 결과를 체크 표시로 함께 보여 준다.

**교차검증 가이드라인 (`교차검증가이드라인.png`)**
- [ ] 정답이 하나뿐이다. 다르게 해석될 수 있으면 조건(예: 면적 기준, 2024년 기준)을 질문에 적었다.
- [ ] '가장·최초·최대' 같은 최상급 표현에 측정 기준(면적, 길이, 해발고도, 최대 수심 등)을 적었다.
- [ ] 시점과 범위가 명확하다. 바뀔 수 있는 정보에는 시점을, 비교에는 지리적·분류적 범위를 적었다.
- [ ] 의심스러운 정보는 2개 이상 출처로 확인했고, 논란이 있는 내용은 주류 학설을 따랐다. 확인하지 못했으면 그렇다고 적었다.

**프로젝트 규칙 (CLAUDE.md, PRD 8장)**
- [ ] 스키마가 `id, category, question, options[4], answerIndex, explanation, difficulty`를 지킨다.
- [ ] '모두 정답', '정답 없음' 보기가 없다.
- [ ] 보기 길이와 형식이 비슷하다. 정답만 길거나 형식이 다르면 힌트가 된다.
- [ ] 인구, 현직 인물, 기록처럼 시점에 따라 바뀌는 사실은 쓰지 않았다.
- [ ] 정치·종교 등 논쟁적 소재가 아니다.
- [ ] 기존 문항과 주제가 겹치지 않는다.

하나라도 통과하지 못하면 그 후보는 버리고 새 소재로 다시 만든다.

## 6. 보고 형식

```
## 새 퀴즈 후보: 지리 / normal

(3장 형식의 JSON)

### 검증 결과
- [x] 정답 유일성: ...
- [x] 최상급 표현 기준: 해당 없음 / "면적 기준" 명시
- ...

### 비고
- 교차 확인 필요 사항
- 같은 카테고리 난이도 분포: easy 4 · normal 4 · hard 2 (권장 4·4·2)
```

## 7. 반영 방법 (사용자가 고를 때만)

후보를 보여 준 뒤 반영 방법을 묻는다. 사용자가 고르기 전에는 파일을 고치지 않는다.

- **기존 문항과 교체**: 같은 카테고리에서 바꿀 문항을 사용자가 고르면, 그 문항의 `id`를 유지한 채 내용을 바꾼다. 40문제·10문제 구조가 유지된다. 난이도가 달라지면 권장 분포(4·4·2)가 깨지는지 알린다.
- **문제 은행 확장**: 카테고리당 10문제를 넘기려면 먼저 `getRoundQuestions()`가 10문제만 뽑도록 고치고 테스트를 바꿔야 한다. 이것은 별도 작업이므로 이 스킬에서 하지 않고, 필요하다고만 알린다.

교체가 승인되면 다음 순서로 진행한다.

1. `src/data/questions.json`에서 승인된 문항만 바꾼다.
2. `npx vitest run src/lib/questions.test.ts`로 스키마와 정답 위치를 확인한다.
3. `context-notes.md`의 결정 표에 바꾼 id, 이전 내용 요약, 이유를 추가한다.
4. 커밋 메시지는 한 문장으로 쓴다. (예: "GEO-004를 지리 normal 새 문항으로 교체")
