# 상식 퀴즈 게임 — Claude Code 구현 3단계 프롬프트

PRD를 '기반·데이터 → 게임 플레이 → 순위·마감' 3단계로 나눴습니다. 한 단계씩 실행하고, 완료 기준을 직접 확인한 뒤 다음 단계로 넘어갑니다.

| 단계 | 목표 | 산출물 | PRD 근거 |
| --- | --- | --- | --- |
| 1단계 기반·데이터 | 프로젝트 뼈대 + 40문제 문제 은행 | questions.json, 출제 함수, 검증 테스트, CLAUDE.md | 4장, 8장 |
| 2단계 게임 플레이 | 시작 → 40문제 → 결과까지 한 판 완주 | 화면 5종, 상태 관리, 점수 로직 + 테스트 | 4~7장, F-01~F-07, F-09 |
| 3단계 순위·마감 | 순위 기록 + 품질 점검 + 빌드 | 순위표, README, 빌드 결과, P0 점검표 | 7장, 9장, F-08 |

## 사용 순서

1. PRD 문서를 Markdown으로 내보내 프로젝트 폴더 맨 위에 `PRD.md`로 저장합니다.
2. 그 폴더에서 Claude Code를 실행합니다.
3. 아래 프롬프트를 1 → 2 → 3 순서로 하나씩 붙여 넣습니다. 각 단계가 끝나면 직접 실행해 완료 기준을 확인합니다.
4. 완료 기준을 못 맞춘 항목이 있으면 이렇게 요청합니다.
   > 완료 기준 중 실패한 항목만 원인을 찾아 고쳐줘. 다른 코드는 건드리지 마.

기술 스택은 Vite + React + TypeScript 기준입니다. 코딩 입문자 실습이라면 1단계의 기술 스택 줄을 'HTML·CSS·JavaScript 파일만 사용, 빌드 도구 없음'으로 바꿉니다.

---

## 1단계 — 기반과 문제 은행

```text
[1단계] PRD.md를 읽고 상식 퀴즈 게임의 프로젝트 기반과 문제 은행을 만들어 줘.
코드를 쓰기 전에 구현 계획을 10줄 이내로 먼저 보여주고, 내 확인을 받은 뒤 진행해.

## 목표
게임 뼈대와 40문제 데이터를 준비한다. 게임 화면은 아직 만들지 않는다.

## 기술 스택
- Vite + React + TypeScript, 서버·DB 없음
- 테스트: Vitest

## 할 일
1. 프로젝트 생성. 폴더: src/data, src/lib, src/components, src/screens
2. src/data/questions.json 작성 (PRD 8장 스키마: id, category, question, options 4개, answerIndex, explanation, difficulty)
   - history, science, geography, general 각 10문제, 총 40문제
   - 카테고리별 난이도: 쉬움 4, 보통 4, 어려움 2
   - PRD 8장 검수 체크리스트 준수 (정답 1개, 시점 따라 바뀌는 사실 제외, '모두 정답' 보기 금지, 보기 길이 비슷하게)
3. src/lib/questions.ts: 카테고리별 문제 로드, 문제 순서와 보기 순서를 섞고 섞인 뒤의 정답 위치를 다시 계산하는 함수
4. 데이터 검증 테스트: 총 40문제, 카테고리별 10문제, id 중복 0건, 보기 4개, answerIndex 0~3, 해설 존재
5. CLAUDE.md: 프로젝트 개요, 실행·테스트 명령어, 코딩 규칙(PRD.md를 기준 문서로 삼을 것)

## 완료 기준
- npm run dev 실행 시 빈 화면이 정상으로 뜬다
- npm test 전부 통과
- 마지막에 40문제를 표(카테고리 / 문제 / 정답 / 해설)로 보여줘. 내가 사실 관계를 검수한다.
```

## 2단계 — 게임 플레이

```text
[2단계] PRD.md 4~7장을 기준으로 게임 진행 화면을 구현해 줘.
구현 계획을 먼저 보여주고, 내 확인을 받은 뒤 진행해.

## 목표
시작 화면 → 40문제 풀이 → 결과 화면까지 한 판이 끝까지 돌아가게 만든다. 순위 저장은 3단계에서 하므로 지금은 만들지 않는다.

## 구현 범위 (PRD 5장 기능 ID)
- F-01 시작 화면: 게임 소개, 규칙 요약, [게임 시작] 버튼
- F-02 문제 출제: 1단계 함수 사용, 라운드 순서 한국사 → 과학 → 지리 → 일반상식
- F-03 진행 표시: 라운드명, n/40, 현재 점수, 진행 바
- F-04 답 선택·잠금: 한 번 고르면 확정, 이후 보기 비활성화
- F-05 즉시 피드백: 정답 초록·오답 빨강 + 'O 정답'/'X 오답' 텍스트 병행, 정답 보기 강조, 해설 표시
- F-06 다음 문제·라운드 전환: [다음] 버튼, 10문제마다 라운드 결과 화면(라운드 점수 x/10)
- F-07 결과 화면: 총점(400점 만점), 정답률, 카테고리별 점수, 소요시간, 등급(PRD 7장 표)
- F-09 다시 하기: 모든 상태 초기화 후 새 게임

## 구현 규칙
- 게임 상태는 useReducer 하나로 관리. 단계: start / playing / feedback / roundEnd / result
- 점수·정답률·등급 계산은 src/lib/scoring.ts 순수 함수로 분리하고 단위 테스트 작성
- 키보드 1~4로 보기 선택, Enter로 다음
- 모바일 360px 폭에서 레이아웃이 깨지지 않을 것

## 완료 기준
- 한 판을 끝까지 플레이했을 때 카테고리별 점수 합 = 총점
- 보기를 빠르게 연타해도 점수는 1회만 반영
- npm test 전부 통과
- 마지막에 F-01~F-07, F-09 구현 여부를 체크리스트로 보고해 줘
```

## 3단계 — 순위 기록과 마감

```text
[3단계] PRD.md 7장(점수·순위)과 9장(비기능 요구사항)을 반영해 MVP를 완성해 줘.
구현 계획을 먼저 보여주고, 내 확인을 받은 뒤 진행해.

## 할 일
1. F-08 순위 기록
   - 결과 화면에서 닉네임 입력 (2~10자, 공백만 입력 불가)
   - localStorage 키 quiz_leaderboard에 최대 50건 저장, 화면에는 Top 10 표시
   - 정렬: 총점 내림차순 → 소요시간 오름차순 → 기록 시각 오름차순
   - 방금 등록한 기록 강조, Top 10 밖이면 '내 순위 N위' 따로 표시
   - localStorage를 못 쓰는 환경에서도 게임은 정상 진행 (try/catch, 안내 문구)
2. 순위표 화면: 시작 화면과 결과 화면에서 진입
3. 비기능 점검: 명도 대비 4.5:1, 키보드 포커스 표시, 360px 모바일 레이아웃
4. 테스트 추가: 순위 정렬, 동점 처리, 50건 초과 시 최하위 삭제
5. README.md: 실행 방법, 문제 추가 방법(questions.json 수정 → 검증 테스트 실행)
6. npm run build 성공 확인

## 완료 기준
- 새로고침 후에도 순위 유지
- 동점 기록은 소요시간이 짧은 순으로 정렬
- npm test, npm run build 모두 통과
- 마지막에 PRD 5장 P0 기능 F-01~F-09 충족 여부를 표(기능 / 충족 여부 / 확인 방법)로 보고해 줘
```
